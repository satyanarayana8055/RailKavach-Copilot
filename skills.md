# RailKavach Copilot — Agent Skills Specification
> **Platform:** RailKavach AI Ecosystem (WDD • Locate • Railcomm) & RailKavach Copilot  
> **Organization:** AiSPRY Technologies | **Target:** Indian Railways Operations  

This document defines the specialized **Google AI Agent Skills** powering **RailKavach Copilot**. These skills bridge the three core RailKavach production modules into an autonomous conversational safety assistant for Indian Railways officers (Sr DEE/TRO, crew controllers, and zonal safety cells).

## 2. Skill 1: `railcomm_audio_search`

### Purpose
Retrieves and analyzes speech-to-text transcripts generated by the **Railcomm Audio Analytics** deep learning denoising pipeline (CNN + RNN + U-Net + Transformer). Denoises 9+ railway noise classes and extracts safety-critical vocabulary between Loco Pilot (LP), Assistant Loco Pilot (ALP), Guard, and Station Master (SM) / Section Controller (SC). Handles railway jargon in Hindi, English, and Hinglish.

### Crucial Safety Vocabulary
Identifies and preserves: **Caution, Stop, Signal, Block, Line Clear, Loop Line, Brake Pipe (5 kg/cm²), Train Numbers, Emergency Brake**.

### Fail-Open Architecture Note
Tracks whether the audio stream was processed normally or bypassed via the **Fail-Open** safety fallback.

### Tool Signature
```json
{
  "name": "search_railcomm_transcripts",
  "description": "Searches Railcomm denoised cab-radio communications by keywords, section, train number, or time range.",
  "parameters": {
    "type": "object",
    "properties": {
      "train_no": {
        "type": "string",
        "description": "Train number (e.g., '12414', 'BOXN-542')"
      },
      "section": {
        "type": "string",
        "description": "Railway section/division (e.g., 'Bikaner-Suratgarh', 'Jaipur-Rewari')"
      },
      "keyword": {
        "type": "string",
        "description": "Keywords in Hindi or English (e.g., 'लाल सिग्नल', 'Caution Order', 'Loop Line', 'Emergency')"
      },
      "start_time": {
        "type": "string",
        "description": "Start timestamp in ISO 8601 or HH:MM:SS"
      },
      "end_time": {
        "type": "string",
        "description": "End timestamp in ISO 8601 or HH:MM:SS"
      }

    "required": ["keyword"]
  }
```

## 3. Skill 2: `locate_cabin_violations`

### Purpose
Queries computer vision detections from **Locate (Locomotive Cabin Video Analytics)** on CVVRS footage. Detects and tracks safety violations while strictly filtering out compliant tasks.

### The 5 Violation Categories
1. `MOBILE_PHONE` – Driver mobile phone usage while operating.
2. `SLEEPING` – Micro-sleep, eye closure, drowsiness.
3. `EATING_DRINKING` – Food/beverage consumption during active train control.
4. `HAND_SIGNAL_NOT_RETURNED` – Failure to return exchange hand signals at stations/gates.
5. `UNAUTHORIZED_PERSON` – Presence of non-rostered personnel in the locomotive cab.

### The 3 Compliant Activities (Non-Violations)
*Must NOT be classified as violations:*
1. `WALKIE_TALKIE` – Legitimate operational radio communication.
2. `READING_WRITING` – Reviewing Caution Orders or signing logbooks.
3. `CONTROLLING` – Operating master controller, vigilance pedal, or brake handles.

### Verification Status Rule
Distinguishes between raw AI detections (`PENDING_VERIFICATION`) and human reviewer-confirmed infractions (`CONFIRMED` / `REJECTED`).

### Tool Signature
```json
{
  "name": "get_locate_cabin_violations",
  "description": "Fetches verified and pending cabin video violation events from CVVRS footage.",
  "parameters": {
    "type": "object",
    "properties": {
      "loco_id": {
        "type": "string",
        "description": "Locomotive identification number (e.g., 'WAP-7 30452')"
      },
      "violation_type": {
        "type": "string",
        "enum": ["MOBILE_PHONE", "SLEEPING", "EATING_DRINKING", "HAND_SIGNAL_NOT_RETURNED", "UNAUTHORIZED_PERSON", "ALL"],
        "description": "Category of cabin safety violation"
      },
      "verification_status": {
        "type": "string",
        "enum": ["ALL", "CONFIRMED_ONLY", "PENDING_ONLY"],
        "description": "Filter by human reviewer verification status"
      },
      "min_confidence": {
        "type": "number",
        "description": "Minimum confidence threshold (0.0 to 1.0)"
      },
      "time_window": {
        "type": "string",
        "description": "Target time or interval (e.g., '02:00:00 - 05:00:00')"
      }
    },
    "required": ["loco_id"]
  }
}
```

## 4. Skill 3: `wdd_wagon_damages`

### Purpose
Queries the **Wagon Damage Detection (WDD)** platform data captured by 6 gantry camera streams (entry and exit gantries). Correlates PaddleOCR wagon identification numbers with YOLOv11-L detections across 8 damage classes, providing entry-versus-exit condition differentials.

### The 8 Damage Classes
`BODY_PANEL`, `DOOR_DEFECT`, `BOGIE_CRACK`, `COUPLER_DAMAGE`, `HANDRAIL_BROKEN`, `BRAKE_BEAM_DEFECT`, `SPRING_BROKEN`, `LADDER_DAMAGE`.

### Tool Signature
```json
{
  "name": "get_wdd_wagon_damages",
  "description": "Retrieves freight wagon damage detections and entry-versus-exit comparison records.",
  "parameters": {
    "type": "object",
    "properties": {
      "train_no": {
        "type": "string",
        "description": "Train number or rake identifier"
      },
      "wagon_no": {
        "type": "string",
        "description": "Specific wagon serial number extracted via PaddleOCR"
      },
      "damage_class": {
        "type": "string",
        "enum": ["BODY_PANEL", "DOOR_DEFECT", "BOGIE_CRACK", "COUPLER_DAMAGE", "HANDRAIL_BROKEN", "BRAKE_BEAM_DEFECT", "SPRING_BROKEN", "LADDER_DAMAGE", "ALL"]
      },
      "comparison_mode": {
        "type": "string",
        "enum": ["ALL", "NEW_DAMAGE_AT_EXIT_ONLY"],
        "description": "Filter to only show damage newly sustained during transit"
      }
    }
  }
}
```

## 7. Skill 6: `safety_pattern_anomaly_engine`

### Purpose
Aggregates safety infractions across divisions, loco pilots, sections, and shifts to identify systemic operational hazards before accidents occur (e.g., fatigue clusters between 02:00–05:00 AM or recurring callout protocol non-compliance).

### Tool Signature
```json
{
  "name": "analyze_safety_patterns",
  "description": "Detects cluster anomalies and repeat violation trends across crews, sections, and shifts.",
  "parameters": {
    "type": "object",
    "properties": {
      "group_by": {
        "type": "string",
        "enum": ["CREW", "SECTION", "TIME_OF_DAY", "VIOLATION_TYPE", "WAGON_DEFECT"],
        "description": "Dimension along which to aggregate patterns"
      },
      "date_range": {
        "type": "string",
        "description": "Analysis period (e.g., 'LAST_7_DAYS', 'OCT_2026')"
      },
      "min_occurrences": {
        "type": "integer",
        "description": "Threshold for flagging as repeat pattern (default 3)"
      }
    },
    "required": ["group_by"]
  }
}
```

## 8. Agent Operating Instructions

```text
You are RailKavach Copilot, the AI safety investigation assistant for Indian Railways developed by AiSPRY Technologies.
You assist railway safety officers (Sr DEE/TRO), crew controllers, and statutory inquiry committees.

Operating Principles:
1. Ground every statement with exact timestamps: [HH:MM:SS] or [Date HH:MM:SS].
2. Distinguish raw AI predictions from Human Reviewer Confirmed decisions (never claim an unverified AI alert is a confirmed violation).
3. Distinguish compliant activities (walkie-talkie, reading/writing, controlling) from safety violations (mobile phone use, sleeping, eating/drinking, hand signal not returned, unauthorized occupant).
4. Strictly maintain Indian Railways terminology (SPAD, Home Signal, Distant Signal, Caution Order, Loop Line, Brake Pipe 5 kg/cm², Loco Pilot, Guard, Station Master).
5. Respect Railcomm's Fail-Open principle: indicate if any audio segment was processed under fail-open bypass.
6. Provide dual-language fluency in English and Devanagari Hindi.
```
